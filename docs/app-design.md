# 知言应用设计规范

知言应用（`app/`，包名 `com.satori.wx`）是知言模块的原生管理界面。打开它的人只想知道三件事：**服务通了没有、断在哪一环、下一步做什么**。其次才是改端口与令牌、导出诊断。发送没有开关：客户端连着就能发，不连就发不了，这本来就是「开关」。界面围绕这个顺序组织，其余一概不做。

## 体系分工与裁决

**视觉只有一个体系：Material 3 Expressive。** Apple HIG 只作为交互与平台体验准则，从不借用它的控件外观。冲突时按 **平台惯例 > 可用性与无障碍（WCAG 2.2 AA）> M3E > HIG 的交互习惯** 裁决。

| 来源 | 在知言中负责 | 不负责 |
| --- | --- | --- |
| Android 平台 | 全屏绘制与安全区、系统返回与预测性返回、对话框按钮顺序、剪贴板敏感标记、系统分享、`FLAG_SECURE` | — |
| Material 3 Expressive | **全部视觉**：颜色角色（HCT / Tonal Spot / 2025 规范）、字阶与强调字阶、形状刻度与形状形变、弹簧动效、分段列表、连接按钮组与切换按钮、描边输入框、搜索栏、全屏对话框、底部工具栏、加载指示器、信息条、开关与复选框、Material Symbols Rounded 图标 | 不牺牲对比度、触达面积与重排 |
| Apple HIG | **交互原则**：大标题随滚动收进顶栏、每屏一个主操作、层级导航、破坏性与高风险操作先确认且默认焦点在取消、可撤销、保留草稿、离开前问保存 | 不仿 iOS 控件，不改 Android 的按钮顺序与返回语义 |

与姊妹应用知弦的区别是刻意的：知弦还混用了 Miuix 的连续曲率与 Carbon 的表单 / 定义列表，知言按「禁止混用其他视觉体系」全部换回 M3E 的原生做法：圆弧角、M3 描边输入框（浮动标签）、M3 列表项。

裁决记录：

- **固定品牌色，不跟随壁纸取色。** 动态色无法为任意壁纸保证 success / warning 两个自定义角色的对比度，也会与青色（`#00838F`）的应用图标分叉。可用性与产品一致性优先。
- **中文取消字距。** M3 字阶给拉丁文的正字距会把汉字拆散；这是语言惯例对规范数值的修正，不是引入别的体系。
- **按钮可视 40dp、触达 48dp。** M3E 的 S 号按钮可视高 40dp，形状在 48dp 触达区里上下各留 4dp（WCAG 2.5.8、HIG 44pt）。
- **徽章用 `on_*_container` 填充。** 2025 规范的错误容器色很饱和，`error` 实色放在 `error_container` 上只有 2.4:1；改用 on-container 填充、容器色图标，对比度即文字配对的 ≥ 4.5:1（`DesignTokenTest` 钉住）。
- **对话框按钮顺序用 Android 的**（肯定操作在最右）；从 HIG 只取错误色与默认焦点。
- **不做「暂停自动刷新」。** 页面只在前台轮询，内容不变就不重绘也不朗读，没有持续运动，WCAG 2.2.2 所针对的干扰不存在。
- **关闭系统动画时一切动效直接跳到终态**，动效从不承载唯一信息。

## 信息架构

```text
首页（状态）                              设置
├─ 大标题 知言                            ├─ 大标题 设置
├─ 状态卡片：徽章 → 结论 → 说明 → 下一步    ├─ 生效状态卡片（可重启微信）
├─ 指标：已发出 · 发送失败                  ├─ 连接：端口、令牌（显示/生成/复制）
├─ 连接链路：微信 → 知言服务 → 账号 → 发送   └─ 底部工具栏（有改动时出现）
├─ 客户端接入：服务地址（不带 /v1）、令牌
├─ 微信：打开微信、重新启动微信
└─ 诊断：版本、计数、上次发送、保活 · 复制 / 分享报告
```

- 窄屏：首页 → 设置是层级导航（顶栏齿轮进入，左上返回），M3 共享轴 X 动效；Android 14+ 预测性返回。
- 宽屏（≥ 840dp 且每栏按字号折算后 ≥ 360dp）：首页与设置并列为列表-详情双栏，右栏降一级表面色，齿轮入口消失。
- 状态的排查顺序（首个不满足的即结论）：Root → 模块已安装 / 待重启 → 模块未停用 → 配置有效 → 服务应答（登录与否）→ 令牌待生效 → 微信已安装 → 微信在运行 → 服务无响应。

## 设计令牌

依赖方向固定：**资源令牌 → `Tokens` → 组件 → 页面**。令牌经 aapt 生成的 `R` 类引用，名字拼错编译失败；界面代码里不许出现字面色值或按名字查资源（`DesignTokenTest` 拦截）。

| 类别 | 唯一来源 | 取值 |
| --- | --- | --- |
| 颜色 | `res/values*/tokens.xml`，由 `tools/make-tokens.py` 生成 | 种子 `#00838F`，Tonal Spot，spec 2025；success / warning 为 harmonize 后的自定义色；深浅两套角色集合一致 |
| 字级 | `dimens.xml` 的 `md_type_*` | M3 字阶 12 档（sp）；字重 400 / 500，强调字阶 600（页面大标题、状态结论） |
| 间距 | `md_space_*` | 2 / 4 / 8 / 12 / 16 / 24 / 32 / 48dp；2dp 只用于分段缝隙 |
| 形状 | `md_shape_*` | 4 / 8 / 12 / 16 / 20 / 28 / 32 / 48dp，外加 full；分段列表首尾 20dp、中间 4dp；状态卡 32dp；对话框 28dp |
| 尺寸 | `md_size_*` | 触达 48；按钮 S 40 / M 56；输入框与搜索栏 56；列表单行 56、双行 72；顶栏与工具栏 64；开关 52×32；复选框 18 |
| 动效 | `md_spring_*` | 标准空间弹簧 ζ0.9（1400 / 700 / 300）、表现力 ζ0.6·800 与 ζ0.8·380、效果弹簧 ζ1.0（3800 / 1600 / 800） |
| 状态层 | `md_state_*` | 悬停 8%、焦点 10%、按压 10%、禁用容器 12%、禁用内容 38%；遮罩 32% |
| 响应式 | `md_bp_*`、`md_reflow_*` | 600 / 840dp；双栏每栏 ≥ 360dp、并排每行 ≥ 280dp，均按 **宽度 ÷ 字号倍率** 判断 |
| 图标 | `res/drawable/ms_*.xml`，由 `tools/make-icons.py` 从 `artwork/symbols/` 生成 | Material Symbols Rounded（权重 400、24dp）；常态用描边，结论用实心 |

## 交互约定

- **配置**：保存只写 `/data/adb/modules/satori_wx/satori-wx.conf`（原子写入：临时文件 → 0:0、0600、`module.prop` 的 SELinux 上下文 → rename → 读回比对；有待生效的模块更新时一并写 `modules_update`）。写出的文件必须能被服务端 `ReadConfig` 接受。服务端是 fail-closed，坏一个字节服务就不启动。
- **生效**：配置只在微信主进程启动时读取。设置页比对文件与运行状态，说清「已生效 / 还有哪几项没生效」，并提供「重新启动微信」（结束微信并立即重新打开，确认后执行）。改了端口或令牌时，应用记住仍在运行的旧入口，重启前的状态探测照样连得上。
- **保活与唤醒锁**：常驻状态通知与唤醒锁都由模块在微信进程内持有 / 发布；通知上的唤醒锁按钮是显式广播，落到本应用的 `keepalive.WakeToggleReceiver`，它把 `{"on":…}` 转到回环的 `POST /v1/internal/wakelock`。应用只做转发，不自己发通知、不持有锁。
- **后台运行**：判定「微信被系统冻结」时，状态卡片的主操作是「打开微信」（回到前台即恢复），次要操作「后台运行设置」打开微信的系统应用详情页，由用户自己在系统里允许后台运行；「微信」分组里常驻同一入口。知言只走系统公开的设置入口，不替用户改系统策略。
- **配置无效**：首页给「修复配置」，设置页用文件里还认得出的端口与令牌填表，保存即重写。
- **令牌**：默认隐藏；显示期间窗口 `FLAG_SECURE`，离开设置页或进入后台立即重新隐藏；复制时标记为敏感内容。
- **草稿**：有改动才出现工具栏；放弃与离开未保存的页面都先确认（取消 / 放弃 / 保存）；草稿跨实例重建保留。
- **服务地址不带 `/v1`**：Satori 把协议版本写进路径（`/v1/{资源}.{方法}`、`/v1/events`），标准客户端拿基础地址自己拼版本段；应用只给基础地址一行，免得用户照抄出 `/v1/v1`。
- **复制**：Android 13 起系统自己提示复制结果，应用不再重复提示。

## 数据与性能

- 不解析 XML 布局，视图直接构造；设置页在首次进入时才建。
- 主线程零 I/O：回环探测在一条工作线程，`su` 在另一条（最长 20 秒，不能堵住刷新）。
- 只在前台轮询：在线 5 秒、离线 10 秒、重启微信期间 2 秒。刚探测到微信没在运行或被冻结时不发 HTTP 请求（冻结时连接能建立却没人应答，只会白等读超时）。root 探测只在首次、回到前台超过 15 秒、服务不应答或操作之后进行，不随每次轮询调用 `su`。文本只在变化时写入，不重复触发读屏播报。

## 验证与范围

目标是按 WCAG 2.2 AA 的适用要求实现原生界面，不把自动测试等同于合规认证。

- `app/test.sh`：`ConfTest` 把 33 个样例同时交给 Java 与服务端真正的 `ReadConfig`（链接 `native/server.cpp`）判定并逐条比对，`Conf.write` 的输出必须被服务端接受；`StatusTest` 覆盖每一种断点、待生效说明、被拦下提示与报告脱敏；`DesignTokenTest` 钉住深浅两套 32 对文字（≥ 4.5）与 17 对非文字（≥ 3）对比度、刻度与字面色值禁令；有 `su` 时 `RootScriptTest` 在临时目录上真跑写入与探测脚本（权限、属主、上下文、读回）。
- `app/tests/ui/run.sh`（真机，不连服务、不调 su、不点屏幕）：离屏渲染 11 种页面 / 状态 / 主题 / 字号 / 宽度组合，检查可点控件 ≥ 48dp、图标按钮有名字、读屏可见的文字不被截断，并输出长图供人工复核。
- 尚需人工或设备矩阵验收：TalkBack 连续操作、外接键盘遍历、不同输入法、旋转与分屏、预测性返回手势。

WCAG 对照：1.3.1 结构与标签；1.4.1 不只靠颜色；1.4.3 / 1.4.11 对比度；1.4.4 / 1.4.10 / 1.4.12 缩放、重排与文字间距；2.1.1 键盘；2.2.1 时限可调；2.4.6 标题与标签；2.4.7 / 2.4.11 焦点可见且不被遮挡；2.5.8 目标尺寸；3.3.1 / 3.3.2 错误识别与说明；3.3.4 防误操作；4.1.2 名称、角色、状态；4.1.3 状态消息。
